# 词条：怎么实现、怎么维护、数据存在哪里

> 给项目负责人看的说明，不需要懂代码。

---

## 一、词条是什么，为什么要单独做

公司规定，对外表达必须经过 Marketing 审核。大模型的特点是会把内容「换个说法」，而换过说法的文字，就不再是审核过的原文了。

所以，**已审核的标准表述单独放在一张表里，原样展示，不交给大模型改写**。这张表就是「词条表」。

在页面上的效果是这样的：

1. 回答里只要出现词条表中的名字（或别名），就会显示成**蓝色虚线**；
2. 鼠标移上去，会弹出**词条卡片**：标准表述（短版 / 长版 / 英文）、注意事项、版本、审核日期、来源链接；
3. 卡片上有「复制短版 / 长版 / 英文版」按钮，复制下来的就是审核原文。

## 二、实现原理（一条回答是怎么变成带虚线的）

```
大模型 / RAG 平台返回的回答文字
        │
        ▼
浏览器拿到文字后，用词条表做一次「查找」  ← 这一步不经过大模型，在你的电脑或浏览器里完成
        │   找到「CRDMO」「示例基地A」……
        ▼
把命中的词包成一个特殊标记 <gloss-term data-id="词条ID">
        │
        ▼
页面把这个标记显示成「蓝色虚线」，悬停时按 ID 去词条表取出那一行，显示成卡片
```

关键点：**卡片里的每一个字都直接来自词条表**。大模型就算把回答写错了，也改不了卡片里的内容。

### 匹配规则

| 规则 | 举例 | 说明 |
|---|---|---|
| 词条名和别名都能匹配 | 「公司简介」→ 指向「公司介绍」 | 别名在表里用 `\|` 分隔 |
| **长词优先** | 先匹配「示例集团官网」，而不是其中的「示例集团」 | 避免长词被拆开 |
| 英文按完整单词匹配 | `ours` 不会命中 `yours` 里的 ours | 中文直接匹配 |
| 英文不区分大小写 | `crdmo` 也能命中 `CRDMO` | |
| 少于 2 个字的词不匹配 | | 单字太容易误命中 |
| 代码和链接文字里不匹配 | | 避免把链接弄乱 |
| 只有「已发布」状态的词条参与匹配 | 草稿、已下线的不显示 | 前台永远只展示审核通过的内容 |

对应的代码在 `src/lib/glossary-match.ts`，卡片样式在 `src/components/glossary/GlossaryTerm.tsx`。

## 三、数据存在哪里

这个项目里有**三类数据**，存放位置各不相同：

| 数据 | 存在哪里 | 谁来维护 | 会不会上传到 GitHub |
|---|---|---|---|
| **① 原始资料**（公众号文章、内部 PPT） | **公司 RAG 平台**（约束 C1，必须放在那里） | 你，在 RAG 平台上上传 | ❌ 不会，项目代码里根本没有这些文件 |
| **② 词条表**（审核过的标准表述） | 维护：**在线表格 / Excel**<br>运行：`data/glossary.json` | Marketing 同事 | ❌ 不会，`.gitignore` 已经排除；只有示例文件 `glossary.sample.json` 会上传 |
| **③ 使用记录**（会话、问答、点赞点踩、反馈原因） | `data/app.db`（SQLite，一个文件） | 系统自动记录 | ❌ 不会 |

所以 **GitHub 上只有代码和示例数据，没有任何公司内部内容**。真实的词条和使用记录都只存在于运行服务的那台电脑上（现在就是你的电脑）。

> 备份建议：`data/` 整个文件夹就是全部数据。每周复制一份到公司网盘即可。

## 四、日常维护流程

```
① 在在线表格 / Excel 里新增或修改词条（按模板填写）
② 状态改为「已发布」前，需经过审核人确认
③ 导出为「CSV UTF-8」文件
④ 运行：npm run glossary:import -- 下载的文件.csv
⑤ 完成。服务会自动读取新文件，不用重启，刷新页面就能看到
```

- **模板**：`data/glossary-template.csv`（第一行是表头，第二行是填写示例）。用 Excel 打开后，照着格式填就可以。
- **导入时会自动检查**：缺少必填项（词条 ID、词条名、分类、短版表述、状态），或者词条 ID 重复，都会报错并指出是第几行，不会覆盖原来的文件。
- **下线某个词条**：把状态改成「已下线」后重新导入，不要直接删除那一行，这样以后还能查到历史记录。

### 表格字段（草案，等拿到真实数据后再细化）

| 列名 | 必填 | 说明 |
|---|---|---|
| 词条ID | ✔ | 唯一编号，例如 G001。一旦确定就不要再改 |
| 词条名 | ✔ | 卡片的标题，也用来匹配 |
| 别名（用\|分隔） | | 简称、英文名、俗称 |
| 分类 | ✔ | 公司介绍 / 业务范围 / 基地介绍 / 资质荣誉 / 合规 / 物料…… |
| 标准表述-短版 | ✔ | 一句话的审核原文 |
| 标准表述-长版 | | 一段话的审核原文 |
| 英文表述 | | |
| 适用场景 | | 官网、PPT、新闻稿…… |
| 禁用/易错表述 | | 卡片上会用黄色警示显示 |
| 数据口径与截止时间 | | 涉及数字时必填 |
| 物料链接 / 来源链接 | | 卡片上会显示可点击的链接 |

## 五、词条的来源：AI 提取初稿 + 人工审校

1. 把公众号文章等资料交给 AI，按「需求整理」文档第 5.4 节的提示词，提取出词条初稿（要求**逐字摘录**，并标出不同资料之间不一致的地方）；
2. AI 输出的表格直接粘贴进词条模板，状态填「草稿」；
3. 人工逐条审校。审核通过的，改成「已发布」，并填上审核人和审核日期；
4. 导入系统。

> 内部 PPT 不能交给外部 AI 的话，可以只上传到公司 RAG 平台，再用平台上的智能体帮忙提取。或者由人工直接填写。
